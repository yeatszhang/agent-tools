# 仓库规范维护评测

| 类型 | 输入 | 预期行为 |
| --- | --- | --- |
| 应触发 | 审查当前 AGENTS.md 是否过长 | 区分常驻规则与按需流程，输出证据和建议，不自动修改 |
| 应触发 | 给这个已有项目精简 Agent 指令并修复死链 | 保留项目约束，修复相关路径，不额外接入工具 |
| 应触发 | 为新项目建立 AGENTS.md，并接入 OpenSpec | 参考模板、完成授权的接入、保留原有配置并验证 |
| 不应触发 | 修复业务组件里的渲染问题 | 不因仓库有 AGENTS.md 而启动规范重构 |
| 不应触发 | 润色产品说明 | 使用写作流程 |

## 结果案例

1. **仅审查**：用户没有请求编辑。交付具体问题与位置，不初始化 OpenSpec、不安装依赖。
2. **已有流程**：项目使用其他变更管理方式，只要求精简根指令。保留现有流程，不照模板新增平行计划或规格目录。
3. **无关模板**：普通前端库没有 Agent Runtime。删除 harness 示例和假想安全/运维入口，不建立空目录。
4. **单一来源**：CLAUDE.md 是 AGENTS.md 链接。修改权威文件，不改成两份独立政策。
5. **路径真实性**：路由引用不存在的 Skill。修正或移除入口，不能以“路径格式正确”当作校验成功。

6. **相似而不同**：Web 和 Electron 都有焦点规则，Electron 还涉及窗口隐藏与恢复。保留两个场景的完整本地流程，不以“重复”为由删掉 Electron 步骤或只留差异片段。
7. **完全相同**：两个 Skill 引用同一份未改写的上游原文。可共用仓库快照，检查路径与来源，不为凑本地副本复制原文。
8. **仅有外链**：必需审查步骤只写“去上游查看”。把适用于该 Skill 的完整步骤沉淀到本地参考，保留来源链接；不能声称未读取的上游已验证。

案例需结合真实或隔离项目运行；文档存在不代表行为评测通过。
