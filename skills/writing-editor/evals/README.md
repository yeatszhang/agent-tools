# Evals

建议每个稳定规则至少覆盖一个 case。

## 触发与范围

| 类型 | 输入 | 预期行为 |
| --- | --- | --- |
| 应触发 | 把这段技术总结改得自然一些，保留所有数据 | 输出改写，保留事实、限定词和立场 |
| 应触发 | 参考我这次修改，记录候选表达偏好 | 区分事实纠正与风格偏好；保存证据时先脱敏并显式指定目录 |
| 不应触发 | 解释 React 的并发渲染 | 正常回答问题，不启动改写或学习流程 |
| 不应触发 | 只改这句话的错别字 | 仅校对，不调整语气与结构 |

## 结果案例

1. **不确定性保持**：原文“初步测试可能降低 10% 延迟，尚未做线上验证”。改写必须保留条件、数值与未验证状态，不得改成“延迟降低了 10%”。
2. **立场保持**：原文反对当前阶段引入微服务。可以精简理由，不得为显得全面而改成赞成或无倾向。
3. **学习边界**：用户只修正日期或说“这次写短一点”。不得保存全文或直接升级稳定偏好；明确要求学习时才记录候选。
4. **独立证据**：同一对原文和修改稿保存五次。不能据此认定达到五次独立观察。
5. **脚本输出**：显式输出目录下的样例保留 UTF-8 原文、可读 diff 和带时区元数据；重复调用不覆盖之前的样例；缺少输出目录时不写文件。

这些是回归验收案例，不代表已经完成模型行为评测。脚本检查可运行 `python3 -m unittest discover -s skills/writing-editor/evals -p 'test_*.py'`。
