# 客户端 UI 设计与实现

仓库共享约束见 [AGENTS.md](../../AGENTS.md)。本 Skill 为草案；平台资料覆盖不等于实现已验证。

## 流程

1. 从项目依赖、工程文件和现有组件识别平台、技术栈、版本、输入方式与设备范围。无法确定且影响实现时再提问；不把“客户端”默认解释为 React Native。
2. 读取现有设计资产、导航和状态管理。新增视觉方向可结合 UI/UX 设计流程，但不更换用户选定的框架、组件或平台控件。
3. 根据任务检查[平台适配](references/platforms.md)：移动端重点看安全区、系统键盘、返回/手势和动态文字；桌面重点看焦点、快捷键、窗口尺寸与原生操作惯例。
4. 为涉及的加载、失败、空数据、成功和中断定义可观察反馈；按用户要求交付方案或实现。保留输入和导航上下文，按实际任务处理重试与取消。
5. 对列表、图片或动画问题先定位实际瓶颈；优先复用已有平台能力和依赖，测量后再决定虚拟化、线程与缓存调整。
6. 在可用模拟器、真机或目标桌面环境运行关键路径。记录实际平台、设备/窗口、输入方式和检查状态；不能运行时明确未验证，避免把浏览器预览当作原生验证。

## 边界

- 跨平台复用任务语义与设计 Token 意图，输入行为、单位、控件和导航允许随平台变化。
- RN、SwiftUI、Compose、Flutter 与 Windows 栈的资料仅作按需参考。版本化 API 应核对目标版本的官方文档。
- Electron/Tauri 可以复用一般界面设计判断；上游没有提供完整的宿主、IPC、权限和更新机制规范，不将这部分声称为已覆盖能力。
- 不因上游推荐安装 Expo、动画或列表库，也不默认升级运行时。复杂度由当前项目和已证实问题决定。

## 验证

至少验证当前改动涉及的主任务和故障恢复路径；报告真正运行的部分。触发与结果案例见 [evals](evals/README.md)。
